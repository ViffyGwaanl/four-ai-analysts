### 三张表.xlsx 的结构

- **说明**：工作簿用法、颜色约定、口径。
- **假设**：23 个参数，每个标明性质（规则 / 推断 / 假设 / 情景输入）和出处。用了命名单元格（如 `P_BASE`、`DAYS_Q`、`TAX_RATE`），公式里直接引用。
- **原始数据**：引擎导出的逐季数字原样录入，B 列写明来源字段路径。
- **利润表 / 资产负债表 / 现金流量表**：小计、合计、期末余额全部是公式；资产负债表的现金取自现金流量表，股东权益 = 上期 + 净利润，固定资产 = 上期 + 资本开支 − 折旧；每张表底部有绿色核对行（公式结果 − 引擎数字），全部为 0（最大 0.0001 的四舍五入误差）。
- **分析**：33 个逐季指标 + 18 项全程汇总，全部是公式；下方 8 张图（全部单一纵轴）。
- **模型复现与情景**：用「假设」页参数从头重算产量、成本、存货、收入、利润、现金和权益。黄色情景格留空时复现实际结果（核对行≈0）；在情景格里填入新决策（例如第 2–5 季开工率填 0.7），或改「假设」页的价格系数，期末权益等结果自动重算。
- **决策备注**：每季决策和备注原文。
- 颜色：浅黄底蓝字 = 输入格；白底黑字 = 公式格；浅绿 = 核对格；浅紫 = 关键结果。
- 检查结果：LibreOffice 重算后 2187 个公式没有错误值；交付文件已带计算好的缓存值，打开即可看到数字。我只在 LibreOffice 里实际打开验证过，没有在 Excel 或 WPS 里实际打开测试。

### web/（3D 网页）

- **入口**：`web/index.html`。需要本地 http 服务（ES 模块不能用 file:// 打开，直接双击会看到中文提示）：`cd 交付/web && python3 -m http.server 8000`，浏览器打开 `http://127.0.0.1:8000/`。
- **内容**：一座剖开的工厂模型——洁净室（工具机台数随产能增加，扩产期间显示脚手架）、HBM 产线（第 4 季前处于「研发中」，之后紫色堆叠芯片随 HBM 产量变化）、仓库（货架上的箱子 = 库存千片）、金库（金条和光柱随现金变化）、负债区（珊瑚色借款块，借款还清后消失）、董事会会议室（大屏显示当季和股东权益）、市场行情屏（价格指数曲线）。
- **操作**：自动按季度播放（每季约 2.5 秒，可切 2×，播到 Q16 停止，再点从 Q1 重播）；拖动时间轴或用 ←/→ 切季度、空格播放/暂停；点上方的分区按钮或 3D 标签飞到该区域；右侧面板是当季经营数据和「股东权益 · 现金 · 负债」走势图；左侧可展开当季决策笔记。
- **网址参数**（便于截图和演示）：`?q=1…16`、`autoplay=0|1`、`view=overview|fab|hbm|warehouse|vault|debt|boardroom|market`、`intro=0`（跳过开场镜头）、`quality=low|high`。
- **数字来源**：`web/data/game-data.js`，由 `scripts/build_web_data.py` 从导出数据生成；页面上的每个数字都按十进制四舍五入显示，和 Excel 一致（例如 Q15 现金 123.71、Q16 股东权益 212.64）。
- **示意比例（假设）**：1 个机台模块 = 5 千片/季；1 个仓库箱 = 1 千片；1 层 HBM 芯片 = 1 千片；1 个借款块 = 1 十亿美元；金条和光柱按平方根缩放。这些只影响造型，屏幕上显示的数字都是精确值。扩产「在建」状态按「资本开支 4 季后投产」推断。
- **手机**：面板收成抽屉，关闭阴影和泛光，限制像素比，处理 WebGL 上下文丢失。
- **检查结果**：用无界面 Chrome 按真实时间加载（`scripts/check_web_cdp.mjs`），桌面 1920×1080 的 Q1、Q6 仓库视角、Q16、自动播放，以及 390×844 手机共 5 种情形：全部正常渲染，控制台和异常 0 条，从页面读回的开工率、产能、库存、现金、负债、股东权益、营收、净利润、价格指数与导出数据一致。截图在 `web/preview/`。
- **库文件**：Three.js r185.1，放在 `web/vendor/three/`，运行时不访问外网，页面里没有外部链接。

## 主要数字从哪来

- **所有「实际」数字**（价格、需求、产量、三张表）都来自引擎：`data/raw/export_final.json`，与每季返回的 `data/raw/decide_QNN.json` 一致。Excel、复盘报告、网页用的是同一份导出数据（网页数据文件 `web/data/game-data.js` 由 `scripts/build_web_data.py` 从导出数据生成）。
- **派生指标**（毛利率、存货周转天数、净负债、ROE 等）在 Excel「分析」页用公式计算；网页里出现的同名指标按同一口径计算（见 `scripts/build_web_data.py` 顶部注释）。
- **标注「估算」的数字**（例如「不做 HBM 期末权益少 82.48」）来自复现模型 `scripts/sim.py` 的情景计算，不是引擎输出。复现模型把实际 16 季的净利润、现金、股东权益逐季复现到 0.001 以内；Excel「模型复现与情景」页是同一套公式，第 2–5 季开工率改成 0.7 时，两边都得到 −8.97。
- **没有使用任何网上查到的数字**。财务数字全部来自引擎；唯一的外部资源是 Three.js 库（见「外部资源」）。

## 我做的假设（都不是规则原文）

1. **从报表反推的引擎参数**（`scripts/infer_params.py` 用 16 季数据逐季核对，最大偏差 < 0.001）：普通内存每千片售价 = 0.024 × 价格指数；HBM 每千片售价 = 0.024 × HBM 价格指数；每千片变动成本 0.005；工厂固定费用每季 1.00；折旧 = 2.00 + 已投产资本开支 ÷ 20（资本开支 4 季后投产并开始折旧）；每季固定研发 0.80、销售及管理费用 0.25；净利息 = 1.5% × 期初借款 + 3% × 期初紧急授信 − 0.8% × 期初现金。
2. **分析口径**：每季 91.25 天（365 ÷ 4）；ROE 年化 = 季度 ROE × 4；存货周转天数 =（期初存货 + 期末存货）÷ 2 ÷ 当季营业成本 × 91.25（营业成本含存货跌价，与引擎口径一致）。
3. **情景模型的额外假设**：HBM 产量 = 产量 × HBM 占比（开工率同样作用于 HBM）；现金低于 0.5 时紧急授信补足到 0.5；HBM 需求与我们何时拿到量产资格无关；资本开支低于维持水平时产能按同一公式线性减少。
4. **「重来」方案（复盘第五节）**：假设权益下降导致已有借款超过新的借款上限时，引擎不会强制还款，只是不能再新借。

## 没能核实的事情

- 上面第 1 条的参数是推断，引擎没有公开；它们在 16 季的数据上全部吻合，但没有覆盖到的情形（例如开工率低于 100% 时生产 HBM、资本开支低于 1.5、动用紧急授信）我从未实际触发，引擎在这些情形下的行为无法核实。
- 紧急授信是否有额度上限、何时自动归还，规则没写，我们也从未用过。
- 借款超过下降后的上限时是否会被强制还款（影响复盘里「开局锁定流动性」那条建议的可行性）。
- HBM 订单是否会因为晚拿到资格而减少（新闻说「认证名额紧张」，但引擎里 HBM 需求看起来是外生的）。
- 第 16 季之后市场怎么走：新闻和一致预期暗示「明年可能转平」，但游戏在第 16 季结束，期末权益按引擎规则计算。
